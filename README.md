# IMPORT_FROM_EXCEL

`webenot.importexcel` — независимый модуль для безопасного импорта Excel/CSV в инфоблоки 1С-Битрикс. Он создан с нуля по результатам функционального аудита существующих решений и не содержит их исходного кода.

## Главное

- XLSX, XLS, ODS и CSV через поддерживаемую ветку PhpSpreadsheet.
- Автоматическое распознавание заголовков колонок.
- Предпросмотр листа с выбором конкретной строки заголовков и автоматической подсказкой.
- Автоматическая транслитерация названий в коды свойств: `Мощность двигателя` → `MOSHCHNOST_DVIGATELYA`.
- Автоматическое создание отсутствующих свойств инфоблока; исходный заголовок становится названием свойства.
- Загрузка настоящего списка свойств выбранного инфоблока: существующее свойство можно выбрать по названию и коду, чтобы обновлять его без создания дубля.
- Создание нового инфоблока прямо при настройке профиля или выбор существующего по названию.
- Понятные профили импорта: пошаговая настройка, таблица сопоставления и подсказки к каждому параметру.
- Отдельный рабочий файл для каждого запуска: данные могут меняться, а заголовки проверяются по сохранённому профилю.
- Автоматический выбор листа: сохранённый в профиле лист, если он существует, иначе первый лист книги.
- Пакетная обработка с сохранением позиции и продолжением после тайм-аута.
- Двухэтапный запуск: сначала обязательная проверка без записи, затем явное подтверждение импорта того же файла.
- Настраиваемое формирование символьного кода элемента: из названия, поля уникальности (например, артикула) или без автозаполнения.
- Выбор системных полей Битрикс по понятным названиям с неизменяемым системным кодом, включая тексты и изображения анонса/детальной страницы.
- Для системных картинок и свойств типа «Файл» поддерживаются публичные HTTP/HTTPS-ссылки, пути внутри `/upload` и ID существующих файлов Битрикс; загрузки ограничены 15 МБ и проверяются по фактическому MIME-типу.
- Для галерей можно создать множественное файловое свойство и указать в одной ячейке несколько ссылок — по одной на строку.
- Заголовки с названиями «Фото», «Картинка», «Изображение» и «Галерея» автоматически получают файловый тип, который можно изменить вручную до сохранения профиля.
- Колонки вида «Раздел 1-го уровня», «Раздел 2-го уровня» распознаются как названия уровней вложенности: отсутствующие разделы создаются, а элемент помещается в самый глубокий заполненный уровень.
- Каждый уровень раздела представлен отдельной группой полей по модели Битрикс: ID, название, символьный и внешний коды, активность, сортировка, описание и изображения.
- Разделы ищутся внутри нужного родителя по ID, XML_ID, символьному коду или названию; дополнительные колонки могут обновлять остальные поля найденного раздела.
- Для каждой колонки используется одна выпадашка назначения с подписанными группами по образцу `kda.importexcel`: существующие свойства, создание нового свойства, элемент, тексты, изображения и поля разделов каждого уровня.
- При выборе **Создать новое свойство** открывается отдельное окно с параметрами свойства Bitrix. Название берётся из заголовка Excel, символьный код заполняется транслитерацией и остаётся доступным для изменения. Для существующих свойств и системных полей новый код не показывается и не создаётся.
- Числовые поля и свойства, даты, флаги активности и форматы `text/html` проверяются и преобразуются по своему типу перед записью.
- Для свойства типа **Список** текст ячейки сопоставляется со значением списка по названию; при создании нового списочного свойства недостающие варианты добавляются автоматически.
- Режимы `insert`, `update`, `upsert` и настраиваемое поле уникальности.
- Безопасные преобразования значений без `eval` и пользовательского PHP-кода.
- Построчный журнал, снимки до/после изменения и откат добавлений/обновлений.
- Откат удаляет созданные импортом разделы, если после восстановления элементов они остались пустыми.
- Веб-интерфейс администратора и CLI-команда для cron.

## Требования

- 1С-Битрикс с поддержкой PHP 8.1 или новее;
- PHP 8.1–8.4;
- расширения PHP, необходимые PhpSpreadsheet (`dom`, `fileinfo`, `gd`, `mbstring`, `simplexml`, `xmlreader`, `xmlwriter`, `zip`);
- Composer 2.

Зависимость зафиксирована на поддерживаемой ветке `phpoffice/phpspreadsheet ^3.10.8`, включающей актуальные исправления безопасности и сохраняющей совместимость с PHP 8.1.

## Установка

### Вариант 1 — один файл, без SSH и Composer

1. Скачайте [`install-import-excel.php`](https://github.com/YuryGorshkov/IMPORT_FROM_EXCEL/releases/latest/download/install-import-excel.php).
2. Загрузите этот файл в корень сайта рядом с папкой `/bitrix`.
3. Войдите в Bitrix как администратор и откройте `https://ваш-сайт/install-import-excel.php`.
4. Нажмите **Установить модуль**.

Установщик скачает готовую сборку с зависимостями, проверит SHA-256, безопасно распакует её в `/local/modules/webenot.importexcel`, создаст таблицы и зарегистрирует модуль. По умолчанию установщик удаляет себя после успешного завершения.

### Вариант 2 — через Git и Composer

```bash
cd /path/to/site/local/modules
git clone https://github.com/YuryGorshkov/IMPORT_FROM_EXCEL.git webenot.importexcel
cd webenot.importexcel
composer install --no-dev --classmap-authoritative
```

После этого установите модуль **Импорт из Excel** в административной панели: `Marketplace → Установленные решения`.

Модуль создаёт собственные таблицы:

- `b_webenot_import_profile` — профили;
- `b_webenot_import_job` — задания и прогресс;
- `b_webenot_import_log` — диагностический журнал;
- `b_webenot_import_change` — журнал изменений для отката.

## Быстрый старт

1. Откройте `Контент → Импорт из Excel → Профили импорта`.
2. Создайте профиль и выберите каталог-получатель по названию. Если подходящего инфоблока ещё нет, нажмите **Создать инфоблок** и укажите его название и тип.
3. Загрузите файл-образец и нажмите **Показать первые строки**.
4. Выберите лист книги и отметьте строку с заголовками. Модуль подсветит наиболее вероятный вариант автоматически; для длинной служебной шапки можно начать показ с любой строки.
5. Нажмите **Распознать выбранную строку** и проверьте таблицу сопоставления. В каждой строке выберите назначение. Если выбранный инфоблок уже содержит нужное свойство, выберите его по настоящему названию и коду. Если свойства ещё нет, выберите **Создать новое свойство**: откроется окно, где название будет заполнено из заголовка, а символьный код — его вариантом латиницей. Код и остальные параметры можно изменить до сохранения профиля.
   Для иерархии каталога выберите у соответствующих колонок `Раздел 1-го уровня → Название раздела`, `Раздел 2-го уровня → Название раздела` и так далее. Для кода, описания или изображения того же уровня можно назначить отдельные колонки.
   Если колонка содержит ссылку на изображение, выберите существующее файловое свойство либо **Создать новое свойство**, а в окне укажите тип **Файл / изображение**. Для нескольких картинок включите флажок **Множественное** и размещайте по одной ссылке на строку внутри ячейки.
6. Выберите колонку, по которой модуль будет находить существующие элементы, и источник символьного кода: название, поле уникальности (например, артикул) или без автозаполнения. Затем сохраните профиль. Файл-образец задаёт только структуру и не импортируется автоматически.
7. На странице **Запустить импорт** выберите актуальный рабочий файл. Его строки и значения могут отличаться от образца; заголовки и их позиции должны соответствовать профилю.
8. Нажмите **Проверить файл**. Модуль автоматически выберет сохранённый лист, а если его нет — первый лист книги, сверит структуру и покажет план изменений без записи.
9. Если счётчики и ошибки вас устраивают, нажмите **Выполнить импорт**. Повторно выбирать файл или лист не нужно: в каталог попадёт именно проверенный файл.

У каждого параметра в административной части есть всплывающая подсказка. Дополнительные настройки CSV свёрнуты и не отвлекают от основного сценария.

### Как формируются коды свойств

Алгоритм нормализации:

1. переводит строку в верхний регистр;
2. транслитерирует кириллицу в латиницу;
3. заменяет пробелы и знаки на `_`;
4. схлопывает повторные `_`;
5. добавляет суффиксы `_2`, `_3` при совпадениях;
6. добавляет `FIELD_`, если код начинается с цифры.

Примеры:

| Заголовок Excel | Код свойства |
|---|---|
| Мощность двигателя | `MOSHCHNOST_DVIGATELYA` |
| Номинальное напряжение, В | `NOMINALNOE_NAPRYAZHENIE_V` |
| 100% нагрузка | `FIELD_100_NAGRUZKA` |

Системные заголовки `Название`, `Наименование`, `XML ID`, `Внешний код`, `Код`, `Активность`, `Сортировка` автоматически сопоставляются с полями элемента. Остальные становятся свойствами.

### Разделы и адреса товаров

Внутреннее назначение профиля `SECTION:1:NAME` означает только «название раздела первого уровня» и не попадает в адрес сайта. Для каждого отсутствующего раздела модуль создаёт обычный `CIBlockSection`, связывает его с родителем и формирует символьный `CODE` из названия, если отдельная колонка с кодом не назначена.

Новые инфоблоки создаются с шаблоном детальной страницы:

```text
#SITE_DIR#/#IBLOCK_CODE#/#SECTION_CODE_PATH#/#ELEMENT_CODE#/
```

Например, цепочка `Гидравлические рукава → Длинные рукава` и товар с кодом `chem-master` формирует путь вида `/catalog/gidravlicheskie-rukava/dlinnye-rukava/chem-master/`. Для существующего инфоблока модуль не меняет его URL-шаблоны и настройки ЧПУ компонента: в них также должен использоваться `#SECTION_CODE_PATH#`, если в адресе нужна полная вложенность.

### Изображения по ссылкам

Ссылка из ячейки загружается только при реальном импорте. Можно поместить URL непосредственно в текст ячейки или назначить ячейке внешнюю Excel-гиперссылку — для назначения изображения модуль возьмёт её адрес. Разрешены `http://` и `https://`; перенаправления ограничены, обращения к приватным IP запрещены, TLS-проверка не отключается. После загрузки модуль проверяет фактический тип файла и размер, затем передаёт файл штатному файловому API Битрикса. Строка URL в свойстве не сохраняется.

## Внутренний формат карты

В административной части карта редактируется как обычная таблица. В базе профиль хранится в декларативном JSON-формате:

```json
[
  {
    "column": "A",
    "label": "Артикул",
    "code": "ARTIKUL",
    "target": "PROPERTY:ARTIKUL",
    "required": true,
    "transforms": [{"type": "trim"}]
  },
  {
    "column": "B",
    "label": "Название",
    "code": "NAZVANIE",
    "target": "FIELD:NAME",
    "required": true,
    "transforms": [{"type": "trim"}]
  }
]
```

Доступные преобразования: `trim`, `lower`, `upper`, `replace`, `prepend`, `append`, `number`, `boolean`, `date`, `split`, `join`, `default`. Исполнение PHP-кода и произвольных выражений принципиально не поддерживается.

## CLI и cron

```bash
php local/modules/webenot.importexcel/bin/import.php \
  --document-root=/var/www/example/public_html \
  --profile=1 \
  --file=/var/import/catalog.xlsx \
  --sheet=Лист1
```

Добавьте `--dry-run` для проверки без записи. Команда возвращает ненулевой код, если возникли ошибки строк или фатальная ошибка задания.

## Защита

- принимаются только локальные обычные файлы с расширениями XLSX/XLS/ODS/CSV;
- запрещены URL, PHP stream wrappers и символические ссылки;
- размер файла по умолчанию ограничен 100 МБ;
- формулы не вычисляются, из ячеек читаются исходные значения;
- XML-форматы обрабатываются актуальным PhpSpreadsheet с защитой от XXE;
- все административные операции требуют прав модуля и Bitrix session ID;
- загруженные файлы получают случайные имена и не сохраняются в Git.

## Архитектура

Код разделён на независимые слои: чтение источника, распознавание колонок, преобразование, сопоставление, целевой адаптер, задания и журнал. `IblockGatewayInterface`, `ReaderInterface` и `ReporterInterface` позволяют добавлять Highload-блоки, каталог, SFTP/S3 и очереди без переписывания ядра.

## Текущие границы

Модуль импортирует поля и свойства элементов инфоблоков, их изображения и иерархию разделов. Торговые предложения, цены, остатки, загрузка самой таблицы по удалённому адресу и Highload-блоки заложены как отдельные адаптеры, но пока не входят в готовый пользовательский сценарий.
